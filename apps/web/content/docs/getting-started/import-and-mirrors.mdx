cobalt is designed so that no other host is a dependency. This page explains how history gets here, how copies stay elsewhere, and what happens when a host goes away.

## Bring a repository in from GitHub

Open **New repository, Import existing** and sign in with GitHub. You get a code to enter on github.com; cobalt never stores the GitHub token it receives, only a proof that you may push to the repositories you pick, which lasts ten minutes.

Install the **cobalt GitHub App** on the repositories you want first. Only repositories where the app is installed and where you may push are offered. Each one becomes a repository here and stays in sync with GitHub in both directions: what you push here reaches GitHub, and what is pushed there reaches here. One GitHub repository feeds one repository here.

```bash
cb import github dana-okafor/dotfiles
```

`cb import` shows the same code and waits for you to approve it. From code, `signInWithGitHub` in the SDK does the same.

<Callout title="Public pages never name the origin">
  A repository imported from another host looks like any other project to
  visitors. Where it came from is shown only to you, in your settings.
</Callout>

## Mirror out

Open a repository, then **Settings, Mirrors and sync**. A mirror is a copy on another host.

| Direction | What happens                                                                   |
| --------- | ------------------------------------------------------------------------------ |
| Push      | Everything here is sent to the host. Pushes made there are not brought back.   |
| Two-way   | Git history syncs both ways. Issues and pull requests are also carried across. |
| Pull      | Only changes made on the host are brought here.                                |

What travels depends on the mirror: Git history always does. Issues, pull requests and releases are chosen per mirror. A change and a pull request map to each other, stacks included: see [Changes and pull requests](/docs/concepts/pull-requests).

## When a host fails

Each mirror shows its own state: _In sync_, _Syncing_, _Behind_, or _Needs attention_. If a mirror stops, for example because an access token expired:

- Nothing is lost. Commits wait in a queue here.
- Nothing else changes. Your work, reviews and releases carry on.
- **Reconnect** replays the queue.

The same is true if a host disappears entirely. Remove its mirror and carry on.

## Leaving a host

Turn on **Only accept pushes here** in Mirrors and sync. Pushes to the mirror are rejected with a link back to the repository. Mirrors keep receiving a copy until you remove them.

```bash
cb mirror list
cb mirror remove m2
```

Removing a mirror stops syncing. It never deletes anything on cobalt.
