cobalt is designed so that no other host is a dependency. This page explains how history gets here, how copies stay elsewhere, and what happens when a host goes away.

## Bring repositories in

A repository here can be linked to one repository on **GitHub**, **GitLab** (gitlab.com) or **Codeberg**. It stays in sync with it both ways: what you push here reaches the host, and what is pushed there reaches here. The host stays the authority for branches and tags. One repository there feeds one repository here, and a repository here is linked to one host only.

Open **New repository, Import existing**, pick the host, and choose what to bring: search, select all, and leave out forks or archived repositories. The import runs in the background and the page follows each repository as it arrives. Large repositories take longer; the full history of git itself arrives in about fifteen seconds.

### GitHub

Install the **Cobalt GitHub App** on the repositories you want, then sign in with GitHub. You get a code to enter on github.com; cobalt never stores the GitHub token it receives, only a proof that you may push to the repositories you pick, which lasts ten minutes. Every repository the app is installed on and you may push to is offered.

The app tells cobalt when something is pushed on GitHub, and when a repository is renamed, moved, archived or deleted. A rename or a move is followed on its own.

### GitLab and Codeberg

Connect your account once, in **Settings, Linked accounts**. cobalt keeps the token sealed and renews it when it is about to expire; you are asked again only if the host refuses it. GitLab asks for the `api` scope, which lets cobalt add a webhook to each repository you import: the token can do a great deal, so it is revoked when you disconnect.

Adding the webhook needs the Maintainer role on GitLab, or admin rights on Codeberg. Without it the repository still syncs, but changes made there arrive late: when someone here fetches, or within a few hours. Git LFS objects do not travel between cobalt and GitLab or Codeberg.

```bash
cb import github dana-okafor/dotfiles
cb import https://gitlab.com/dana/zine
cb import batch codeberg dana/notes dana/recipes
```

`cb import` shows the GitHub code and waits for you to approve it. GitLab and Codeberg are connected in the browser; `cb import` tells you when that is still to do.

### Who can push

Access is decided here. Anyone who can write to an imported repository here can push to it on the host through cobalt, even if the host would refuse them. The host's **branch protection rules still apply** to those pushes, and a refused push shows the host's own message. Set up the same rules here before you invite people.

### Pull requests, issues and releases

They come along with the same numbers: pull requests as changes in **Changes**, issues with their comments in **Issues**, published releases in **Releases**. Comments on a pull request show as its reviews. Their authors are shown as people on that host, such as `octocat@github`, never as accounts here, and an import notifies no one. Everything cobalt does with changes and issues works on them, and what is made here next takes the next free number.

The host stays the authority for their title, text and state, and its webhooks keep them current. A pull request whose commits are not in the repository, because it came from a fork or its branch was deleted before it synced, keeps its patch as the host gave it (`repos.provider.pulls.patch`).

### When the link breaks

**Settings, Mirrors and sync** shows how the link is doing and whose account keeps it in sync. If that person disconnects, loses access or deletes their account, the repository and its history stay; pushes to the host are refused with the reason, and an admin of the repository with their own connection can take the link over with **Keep it in sync with my account**.

  A repository imported from another host looks like any other project to

</Callout>

## Mirror out

Open a repository, then **Settings, Mirrors and sync**. A mirror is a copy on another host.

| Direction | What happens                                                                   |
| --------- | ------------------------------------------------------------------------------ |
| Push      | Everything here is sent to the host. Pushes made there are not brought back.   |
| Two-way   | Git history syncs both ways. Issues and pull requests are also carried across. |
| Pull      | Only changes made on the host are brought here.                                |

What travels depends on the mirror: Git history always does. Issues, pull requests and releases are chosen per mirror. A change and a pull request map to each other, stacks included: see [Changes and pull requests](/docs/concepts/pull-requests).

## When a host fails

Each mirror shows its own state: _In sync_, _Syncing_, _Behind_, or _Needs attention_. If a mirror stops, for example because an access token expired:

- Nothing is lost. Commits wait in a queue here.
- Nothing else changes. Your work, reviews and releases carry on.
- **Reconnect** replays the queue.

The same is true if a host disappears entirely. Remove its mirror and carry on.

## Leaving a host

Turn on **Only accept pushes here** in Mirrors and sync. Pushes to the mirror are rejected with a link back to the repository. Mirrors keep receiving a copy until you remove them.

```bash
cb mirror list
cb mirror remove m2
```

Removing a mirror stops syncing. It never deletes anything on cobalt.
