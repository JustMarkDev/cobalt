### `imports.create`

`POST /imports`

**Import a repository from another host**

Makes the repository here and links it to the provider repository in a two-way sync: what is pushed here reaches the provider, and what is pushed there reaches here. GitHub needs `github_access`, which proves you may push to it; GitLab and Codeberg need a connection (`providers.oauth.start`). Anyone who can write here can then push there through Cobalt, and the provider's branch protection still applies. Pull requests, issues and releases follow, read-only. Naturally idempotent like `repos.create`.

| About      |                         |
| ---------- | ----------------------- |
| Safety     | `write`, safe to repeat |
| Needs      | a token                 |
| Scopes     | `repo:write`            |
| Rate limit | `write` pool, 1 unit    |
| Dry run    | `?dry_run=true`         |
| Success    | `201`, a `repo`         |

**Query parameters**

| Name      | Type    | Notes                                                                                                   |
| --------- | ------- | ------------------------------------------------------------------------------------------------------- |
| `dry_run` | boolean | Run every check and change nothing. The answer is what would have been returned, with Cb-Dry-Run: true. |

**Request body**

| Member          | Type                                          | Notes                                                                                                              |
| --------------- | --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `host`          | `github` or `gitlab` or `codeberg` or `gitea` | Required.                                                                                                          |
| `slug`          | string (pattern)                              | Required.                                                                                                          |
| `owner`         | string                                        | Default: the account you act as                                                                                    |
| `name`          | string (pattern)                              | Default: its name on that host                                                                                     |
| `visibility`    | `public` or `private`                         | Default `"public"`.                                                                                                |
| `github_access` | string (up to 4000 characters)                | For GitHub: the `access` from signing in with GitHub (`github.device.poll`). Proves you may push to the repository |

**Errors**

### `repos.provenance`

`GET /repos/{owner}/{repo}/provenance`

**Where a line of code came from**

Follows a line to the conversation that produced it: the commit that wrote it (by blame, up to 200 commits back), the change it landed through, the patch set, and the agent run that pushed that patch set, with its task, summary, links and transcript. With `change`, the line is read in that change's newest patch set instead, and the answer is the patch set of the change that wrote it; a line that was on the base already is followed there.

| About      |                                            |
| ---------- | ------------------------------------------ |

| Needs      | nothing for public data, a token otherwise |
| Scopes     | `repo:read`                                |

### `repos.transfer`

`POST /repos/{owner}/{repo}/transfer`

**Give a repository to another account**

Owners and admins of the repository, into an account where they are an owner or admin. Send `confirm` with the current `owner/name`. The old address answers `308` with the new one. Within the same account it is a rename and everything stays. To another account, only the code, its history and its changes and issues go: secret values, production confirmations, the secrets audit log, webhooks, mirrors, integrations, collaborators, maintainers, team grants, auto-land, declined models, vouched and denounced accounts stay behind, and tokens limited to it stop reaching it. Variable names stay; the new owner sets values.

| About      |                         |
| ---------- | ----------------------- |
| Safety     | `write`, safe to repeat |
| Needs      | a token                 |
| Scopes     | `repo:write`            |
| Rate limit | `write` pool, 1 unit    |
