title: Secrets for agents
description: How an agent runs your code with real values without them landing in its context, and what that cannot stop.
---

An agent needs values to run tests or a dev server. A `.env` file in the working directory ends up in the model's context; a pasted key ends up in a log, a prompt, a commit. So the agent does not get values. It runs a command that has them:

```bash
sx env run --env development -- bun test
```

- The values come from your login on this machine, if you are on the repository's team. An agent you run here uses the same login.
- They go into that one process. Nothing is written to disk.
- Everything the process prints is scrubbed: each value, and its base64 and URL-encoded forms, becomes `«NAME»` before the agent reads it.
- Every read goes in the audit log with the machine, the tool and the model.

## Production waits for you

Development and preview values need nothing more. Production values wait until you confirm this login on a page you are signed in to: `sx` stops with exit 6 and `confirmation_required`, and prints the link. You confirm for one, four or eight hours, for that one machine. A token can confirm nothing, not even its own request, so an agent holding your login cannot let itself in.

## What this cannot stop

- **A command you run can send a value somewhere.** Scrubbing protects what the agent reads, not what the process does. Keep production behind its confirmation, and run agents you do not trust where outbound traffic is limited.
- **An agent on your machine can do what you can.** That is the point of one login. Sign a machine out in **Settings, Machines and tokens** when you stop trusting it.
- **Short values.** A value under four characters is scrubbed only where it stands alone.
- **A file you ask for.** `sx env pull --plaintext` writes `.env.local` (mode 600). It is off by default because that file is what leaks.
