title: Access rules
description: Branches and paths only some people may see, inside a repository many people read.
---

An organization's members can read its repositories. Sometimes a part of one is for fewer people: a branch where three people prepare an acquisition, a folder of contracts, a key file. An access rule says which part, and who.

```bash
curl -X PUT "$CB/repos/northwind/atlas/access-rules/deal" -H "Authorization: Bearer $CB_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"kind":"branch","patterns":["deal/*"],"readers":["dana","hollis","team:legal"]}'
```

| Kind     | Hides                                                                            |
| -------- | -------------------------------------------------------------------------------- |
| `branch` | Branches matching `patterns` (`deal/*`), and every change on them                |
| `path`   | Files matching `patterns` (`finance/**`, `*.key`), and every change touching one |

`readers` are people and `team:<slug>` for a team of the owning organization. The repository's owners and admins always read everything, so a rule never locks its owners out; being a member of the organization is not enough. A rule cannot hide the default branch. **Repository settings, Access** lists the rules; only owners and admins write them.

## What someone outside a rule sees

Nothing of what it hides, anywhere cobalt shows it:

- the change answers `404`, and is not in lists, search, the event feed, the stream, sync, the inbox or the dashboard;
- nobody is notified about it who cannot see it;
- a private path is not in the file tree, and reading it answers `404`, as a file that does not exist; a commit's diff leaves it out;
- a private branch answers `404` as a ref;
- they cannot open a change on a private branch, or one that touches a private path (`403 forbidden`).

Runners registered for the account read all of it: they build the repository. Commit messages on the default branch stay visible; keep secrets out of them.

## What it does not cover yet

`git clone` and `git fetch` go to the git store (code.storage), which does not filter refs or paths per login yet. Until it does, anyone who can clone the repository gets every branch and file. If that matters, keep the material in a repository of its own that only those people can read, or as [secret values](/docs/concepts/secrets#files), which never reach a clone.
