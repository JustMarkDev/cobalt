There is no separate kind of account for agents. An agent works under the login of the machine it runs on, so what it writes is yours, under the same rules as everything else you write. What changes is that every write says how it got here.

## Log in once per machine

```bash
sx auth login
```

The approval page names the machine and says that it will be able to read your team's secret values. Approve it only if you started it yourself. From then on every agent on that machine (Claude Code, Codex, whatever T3 Code runs) uses the same login. There are no keys to paste and nothing that expires in the middle of a task. **Settings, Machines and tokens** lists every machine and token that can act as you, with a button to sign each out.

To give an agent less than you have, make it a personal token with fewer scopes or fewer repositories, and name its machine.

## Receipts

Every write records, next to the account responsible:

| Part    | From                                                     |
| ------- | -------------------------------------------------------- |
| Machine | The login: the name the machine gave when it signed in   |
| Tool    | What the client declares: `sx`, `T3 Code`, an MCP client |
| Model   | What the client declares, such as `Claude Opus 5.5`      |

Orchestrators set `SX_TOOL` and `SX_MODEL` for the agents they start; `sx` and the MCP server send them on every request. A `git push` reads the model from the commit: `Assisted-by: <tool>:<model>`, or a `Co-Authored-By` with a model vendor's no-reply address.

The receipt shows on the change, in the timeline, in the audit log and behind any line of code. source.code hosts no model and cannot check what a tool declares, so tool and model are labels: they grant nothing.

## What a repository takes

In **Settings, Contributions** an owner sets:

- **Declined models.** Changes declared with these models are turned away (`model_declined`). It stops tools that report honestly, which is most of them.
- **Vouched.** People whose changes are listed first. The checks are the same for everyone.
- **Denounced.** Accounts that may not open changes or issues, with the reason they are shown.
- **Land when green.** A change whose checks pass, with no open high finding and the policy met, lands by itself under the account that turned this on. Never a draft, a stacked change, or one that touches CI, policies or the env schema.

## Proof, then one button

Checks are evidence, and the AI reviewer's findings are the independent review. Landing is the person's act: one **Land** button, pressed with or without reading the diff, or the repository's land-when-green. Whoever opened a change can never approve it, from any machine.

## Handing work off

source.code starts no agent. **Hand off** on an issue, a change or a failing pipeline gives you the command that passes it to an orchestrator (T3 Code on your machine, or boat.dev in the cloud). The agent works under your login, opens a draft change, and its writes come back with receipts. See [Agents and the CLI](/docs/cli/agents).
