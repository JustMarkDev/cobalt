A policy says when it applies and what it requires. Policies live in `.source/policy/` and are reviewed like code.

```yaml title=".source/policy/main.yml"
rules:
  - id: ci-evidence # built in: green checks on the tree that lands
    mode: enforce
  - id: findings # built in: no open high finding
    mode: enforce
  - id: reviewed # built in: an approval, not from the author
    mode: dry-run
  - id: storage-owners
    when:
      paths: ['src/store/**']
    require:
      - approval: { min: 1, from: [hollis] }

exceptions:
  - rule: storage-owners
    for: ines
    reason: Release week, covering for hollis
    expires: 2026-11-12
```

<Callout type="warn" title="Design">
  The syntax above is the proposal cobalt is built around. It is not the format
  of any existing tool.
</Callout>

## Parts of a rule

| Key       | Meaning                                          |
| --------- | ------------------------------------------------ |
| `id`      | A name, shown wherever the rule blocks something |
| `when`    | What the rule applies to: `paths`                |
| `require` | What must be true before a change lands          |
| `mode`    | `enforce` (default), `dry-run` or `off`          |

## The same rules for every account

There are no approver classes. Every account follows the same rules, and whoever opened a change never counts as its approver, from any machine. Proof comes first: checks bound to the tree, and the AI reviewer's findings as the independent review. `reviewed` starts in dry run, so an approval is shown, not required, until you enforce it. Every write keeps a [receipt](/docs/concepts/agents#receipts) of the machine, tool and model.

## Evidence

`evidence` ties a check to the tree that will actually land. A green check on an older patch set does not count.

## Exceptions

An exception is named, owned and ends on a date. There is no list of people who bypass everything forever.

## Dry run

Set `mode: dry-run` to see what a rule would block without blocking anything. The Policies page shows the results.

## Policies protect themselves

A change to `.source/policy/` needs a human from the policy owners. An agent cannot approve a change to the rules that govern it.

## From the CLI

```bash
cb policy check 216      # exit 5 when blocked
cb policy explain 216    # list each requirement
```
