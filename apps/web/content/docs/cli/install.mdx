`cb` is one file with nothing else to install: Varlock (which checks your
variables against `.env.schema`) and the MCP server are inside it.

```bash
curl -fsSL https://cobaltforge.dev/install.sh | sh
cb --version
cb auth login
```

On Windows, in PowerShell:

```powershell
irm https://cobaltforge.dev/install.ps1 | iex
```

The script picks the binary for your system from the latest
[release](https://github.com/JustMarkDev/cobalt/releases), checks it against
the release's SHA-256 sums, puts it in `~/.cobalt/bin` (with `cobalt` as a
second name) and adds that folder to your `PATH`. `CB_VERSION=0.2.0` installs a
given release, `CB_INSTALL=/some/dir` another folder.

An agent can install it the same way: the command never asks a question.

## Other ways

With [Bun](https://bun.sh): `bun add -g @cobaltforge/cli`. From a checkout of
the cobalt repository: `bun packages/cli/src/main.ts --help`.

## Shell completion

```bash
cb completion zsh  > "${fpath[1]}/_cb"
cb completion bash > /etc/bash_completion.d/cb
cb completion fish > ~/.config/fish/completions/cb.fish
```

## Updating

```bash
cb upgrade
```

It replaces `cb` with the latest release, checked the same way. Installed with
Bun, update it with `bun update -g @cobaltforge/cli`. Settings in
`~/.config/cb/config.json` are kept.
