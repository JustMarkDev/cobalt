`cb` is the command line for cobalt. `cobalt` is the same command under its full name, so `cobalt change land 216` and `cb change land 216` do the same thing. It is built around two ideas: a script or an agent should never get stuck waiting for an answer, and everything it prints should be easy to read by machine.

<Callout type="warn" title="Preview">
  `cb` runs against built-in sample data until the hosted API is live. Every
  command, flag, output shape and exit code on these pages is real and tested.
</Callout>

## What makes it different

| Principle                 | In `cb`                                                                                                              |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| **No questions**          | There are no prompts. If something is missing, `cb` exits with a message that says which flag to pass.               |
| **Works out the obvious** | The repository comes from your git remote, the change from your branch, the title from your last commit.             |
| **JSON when piped**       | Output is JSON when stdout is not a terminal, or with `--json`. No flag hunt.                                        |
| **Errors you can act on** | Every error has a stable `code` and a `hint` with the next command to run.                                           |
| **Safe to repeat**        | `repo create`, `change create`, `issue create` and `mirror add` return the existing thing instead of duplicating it. |
| **Say before doing**      | `--dry-run` shows what would happen on any command that changes something.                                           |
| **Made for agents**       | `cb context` returns everything an agent needs in one call, without secret values.                                   |

## A tour

```bash
cb change create            # a change from this branch
cb change view              # what blocks it
cb policy explain 216   # which rule asked for that
cb change land              # land it if policy allows
```

Piped, the same commands return data:

```bash
cb change list | jq '.[] | select(.ci == "fail") | .id'
```
